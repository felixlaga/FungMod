# Reproducing the software paper

The submission draft is the short software paper `paper/joss/paper.md`
(Journal of Open Source Software format, with `paper/joss/paper.bib`). It
reports no research results; the workflow `.github/workflows/draft-pdf.yml`
builds its PDF with the journal's own toolchain whenever it changes, and
`tests/test_joss_paper.py` checks its sections, citations and length. The
rest of this page concerns the longer case-study manuscript.

The draft manuscript in `paper/paper.tex` (LaTeX; `make paper-pdf` builds
it) quotes numbers from five recorded
studies on the Gelain 2020 cultures: the joint benchmark (v2), the Bayesian
identifiability study (BAYES-001), stage A and stage B of the preregistered
model-criticism study (CRIT-001 to CRIT-003) and the cross-solver
reproduction in COPASI (PETAB-001). Each study has a runner script, a frozen
plan, a README and checksummed result files under `data/benchmarks/`. This
page is the single entry point for checking or regenerating what the paper
says, in tiers ordered by cost.

## The tables and their manifest

`paper/tables/` holds the paper's five tables twice, as Markdown (for
reading on GitHub) and as LaTeX fragments (`.tex`: a full-width `table`
float with a caption, the label `tab:<name>` and one `tabularx` per table,
which the manuscript pulls in with `\input`), each generated by
`fungal_model.research.paper_tables` from the recorded result files, plus
`manifest.json`, which records for every table the source files, their
SHA-256 digests and the key numbers the text quotes. The tables are never
edited by hand (the first line of each says so); `tests/test_paper_tables.py`
fails when a committed table in either format, the manifest or a source file
drifts from the others, and when the manuscript stops including or
referencing a table.

```bash
python scripts/reproduce_paper.py tables   # regenerate paper/tables and paper/figures (seconds)
python scripts/reproduce_paper.py check    # committed tables and figures match the recorded results (seconds)
```

## The figures and their manifest

`paper/figures/` holds the paper's four figures, drawn by
`fungal_model.research.paper_figures` from the same recorded files (and, for
the measured points, the reviewed literature datasets): the whole-condition
holdouts on the cellulose loadings, the posterior predictive bands, the stage
A screen of the model-criticism study and the cross-solver objectives. Each
figure is written as SVG (for a browser) and as PDF (included by the LaTeX
manuscript) from one matplotlib call; next to them sits a JSON file with
exactly the numbers plotted, and `manifest.json` records the sources with
their digests and the key numbers the captions quote. `check` compares the
data files and the manifest byte for byte and requires each SVG and PDF to
exist and carry the generator marker; the SVG and PDF bytes themselves
depend on the matplotlib version and are not compared.
`tests/test_paper_figures.py` enforces the same and that the manuscript
includes and references every figure.

## Building the manuscript

`paper/paper.tex` is the manuscript; `paper/paper.bib` its references.
`make paper-pdf` runs `latexmk -pdf` in `paper/` and writes
`paper/paper.pdf`, which is not committed (the build products are ignored by
git). It needs a TeX distribution with `latexmk`, `natbib`, `booktabs`,
`tabularx`, `geometry`, `graphicx`, `url` and `hyperref`; `lmodern`,
`caption` and `microtype` are used when present. A full TeX Live has all of
them; on a minimal installation such as TinyTeX run
`tlmgr install natbib booktabs tabularx geometry hyperref url lm caption microtype latexmk`
first. The manuscript never
types a number from a study: it includes the generated table fragments and
figure PDFs, so a stale table shows up as a failing `check`, not as a
silently wrong manuscript.

```bash
make paper-pdf      # paper/paper.pdf from paper/paper.tex, tables/*.tex and figures/*.pdf
```

## Tiers of reproduction

| Tier | Command | What it recomputes | Cost |
| --- | --- | --- | --- |
| `check` | `make paper-check` | nothing scientific: the committed tables, figure data and manifests against the recorded result files and their digests | seconds |
| `verify` | `make paper-verify` | the digest chains of every study against its plan and amendment log; the frozen held-out predictions and stage B artifacts; the cross-solver plan's sources; the compiled-core objective at the recorded cross-solver optimum (must match to 1e-7); the projected cost gradient of the recorded baseline fit (must be below 1e-2 in log space) | about a minute |
| `stage-a` | `make paper-stage-a` | stage A of the model-criticism study (every model and scenario, profiles for models that pass the screen) and the COPASI reproduction, into `outputs/paper_reproduction/`, compared with the recorded held-out errors (relative 1e-6), screens, cross-solver outcome and objectives | about two hours on four cores; needs the `copasi` extra |
| `full` | `make paper-full` | `stage-a` plus the Bayesian study and the three stage B chains through their own scripts, compared on verdict-level fields (convergence flag, identifiability classes, R1 to R3, outcomes) | a day of compute |

The `full` tier compares verdicts rather than digests because the ensemble
sampler is seeded and deterministic on one machine, but floating-point
differences between platforms can move individual samples. Nothing in any
tier changes the recorded results under `data/benchmarks/`.

## Environment and installation

- `requirements-lock.txt` pins the runtime dependency closure, generated on
  CPython 3.13 (its numpy pin needs Python 3.12 or later); the `Dockerfile`
  installs it.
- `make wheelhouse` downloads that closure into `wheelhouse/` and
  `make install-offline` installs the built wheel from it with network
  access disabled (`pip install --no-index --find-links wheelhouse`).
  Continuous integration runs the same offline install on every pull request
  and on pushes to `main`, on the lock's interpreter (CPython 3.13), and then
  runs a virtual experiment from outside the checkout.
- The `copasi` extra (`pip install "fungmod[standards,copasi]"`) is needed for
  the cross-solver tiers only.

## What is not covered

- A tagged, archived release with a DOI is pending; it needs the repository
  owner.
- The review of the biological mapping by a domain researcher is outstanding
  and cannot be produced by the tooling.
- The paper's narrative sentences are not checked word by word; the tables
  and the manifest's key numbers are the checked surface, and the text cites
  them.
